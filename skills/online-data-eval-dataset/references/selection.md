# 材料阅读与代表性筛选

## 先弄清记录是什么

同时盘点Markdown汇总与Excel明细。汇总可能保留有价值的典型需求，Excel可能揭示原始表述、上下文及异常；两者可互补，不能只按文件格式选来源。

Excel按实际表头识别提问、报错、TraceID、会话等字段，不能固定用F列。工作表名称和原分类可能错分。Markdown保留标题、行号和其附近的TraceID、附件引用、频次标记；把汇总转述标为汇总转述，不能称作逐字用户消息。忽略`~$`临时锁文件和本轮生成目录；读取多来源时保留全部路径，不以同名文件覆盖记录。

保留原始文本和位置，另做结构化记录。解析或转换失败要记入覆盖范围，不能静默跳过后声称全量阅读。只显示必要摘录或统计，避免把大型单行JSON整体输出到上下文。

## 区分信息层级

| 记录情况 | 处理 |
| --- | --- |
| “已有记忆＋新增对话＋请输出整合后的完整记忆摘要” | 通常是记忆维护内部请求，结合完整结构判断并标明推断；不当作直接业务问题。新增对话明确完整时，可另提炼其中用户任务，但来源说明必须写明所在层级 |
| 工具名、参数JSON、读取结果、堆栈、报错摘要 | 与提问分列；可以为对应任务提供约束和风险证据，不能直接变成用户需求 |
| “继续执行、已登录、导出Word”等 | 有上下文则并回原任务；无可恢复意图不单独成题。“导出Word”若只是短续接消息，不能猜前面的内容 |
| 问候、报时、简单算术、明确消耗Token的指令 | 通常排除，不作为典型业务能力任务 |
| 只有附件名、断句、指代不明 | 先查会话邻文或原文件。仍不能还原则舍弃或缩小范围；不自行补写成“原问题” |
| 重复运行、轻微改口、不同参数版本 | 合并成需求族，保留代表性原文及其他来源定位；不要只按完全相同字符串去重 |

不要用“含记忆、测试、报错、模拟”等单个词硬删整条记录。例如用户真正要做软件测试或仿真分析时，这些词可能就是业务内容。

## 报错怎样形成可测任务

把三层分开记录：用户原本要做什么；观察到什么异常及证据；为什么值得测，这是已证实的业务约束还是失败原因假设。

例如“导出的表缺列”若可取得预期字段与输入，可提炼为完整交付与字段保真任务；“Tool execution aborted／用户取消／网络超时”本身不能证明能力不足，也不能凭空推断本来要生成何种文件。无法关联到完整业务意图的报错仅列材料问题，不凑成试题。

保留异常触发条件和依赖关系，不复刻真实凭证、私有账号、不可访问的机器路径。若把线上权限问题改成离线文本处理，能力已变化，必须在管理说明中写清。

## 选题判断

每个需求族检查：业务意图与来源能否定位；是否区别于其他候选；素材可得或能公平构造；是否有正式交付与评价依据；复杂度及输入／交付规模是否值得测。

默认规模约30题，是代表性集合而非覆盖所有日志。优先用一题体现一组相关能力；重复出现说明有代表性，但频次可能来自自动重试、内部请求或同一会话，不能直接视为独立用户数量。严重但低频的失败也可入选，前提是证据与任务可恢复。

类别按实际工作目标而非文件后缀划分。Word输出可以是规则审核、研究或内容编制；原生PPT的文本核查属于材料审阅。可从以下粗分类起步，根据真实候选合并调整：A表格数据处理与分析；B材料审阅与规则核验；C基于材料的内容编制；D外部信息检索与研究；E文件整理、程序开发与代码核查。

候选规划同时列“保留／合并／排除／待补证据”的理由。可以提有代表性的邻近问题，但必须绑定真实需求族并标明是由该需求扩展的构造任务，不能说在线上直接出现过。

## 素材恢复边界

真实附件能拿到时读取并核验；只有文件名就不能声称拥有原附件。可用新材料重建同样的业务关系、信息密度和判断难点，但不要只做空壳、把输出答案预填进去，或制造没有规则可解的矛盾。

合理构造包括替换身份与金额、提供清晰的会议记录、建立可计算的多表关系。不可恢复的长期记忆、隐含个人偏好、不能模拟的业务状态和私有系统依赖，不勉强纳入。真实法规、标准和公开网页使用真实来源；自定内部规则与外部事实分开管理。

线上显式调用skill不代表测试前必须安装同名skill。遵循既定测评环境，应用自带能力可保留并记录，不为个别题临时补装不同能力。将可迁移的业务要求明文提供；依赖私有skill且无法公平重建的题目舍弃。用户明确要求考查技能调用时，另行界定依赖和测试范围，不把此类实验混入默认任务集。
