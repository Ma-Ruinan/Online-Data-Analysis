# 目录与工作catalog

## 对外交付

根目录通常只有四份管理文件；每题目录内只有`问题描述.txt`与实际输入，不放答案或说明。

- `数据集说明.md`：当前用途、题量分类、一次提交方式、联网及时间条件、检查边界；不写对话修改日志。
- `题目索引.csv`：编号、类别、题目、相对目录、同目录输入文件、正式交付、联网、素材性质。多文件用中文分号分隔，无附件明确注明。
- `来源与调整说明.md`：逐题写原文件及位置、可用标识、原文／汇总转述／节选、保留意图、改写与补充、素材是原件还是构造、能力范围改变。报错另列证据和推断，不把原因假设写成事实。
- `文件清单.csv`：`相对路径,字节数,SHA256`，覆盖全部实际文件但不对自身求哈希。修改后重建，发布后核对。

规划文件可为`批次名-基于线上数据的测评数据.md`，放在数据集目录外。标题直接说明本批内容，不加多轮讨论笔记或答疑。命名以用户要求为准。

## 工作catalog

这是构建与检查用的内部JSON，保存在工作目录，不作为受测输入。示例见[dataset-catalog.example.json](../assets/dataset-catalog.example.json)。它用于维护题目与材料对应，不能替代原始证据阅读。

```json
{
  "batch": "批次标识",
  "expected_count": 1,
  "cases": [{
    "id": "A01",
    "title": "任务标题",
    "category": "A_表格数据处理与分析",
    "folder": "A_表格数据处理与分析/A01_任务标题",
    "ability": "对象应完成的操作及约束",
    "sources": [{
      "file": "来源文件名或路径",
      "locator": "工作表名!F23，或第12—16行",
      "kind": "user_quote",
      "excerpt": "可回查的原文摘录",
      "trace_id": "存在时记录"
    }],
    "inputs": [{"name": "业务资料.csv", "origin": "constructed", "notes": "补充设定及理由"}],
    "outputs": [{"name": "A01_分析结果.xlsx", "description": "实际交付内容"}],
    "scope_changes": [],
    "network": false
  }]
}
```

`sources.kind`为`user_quote`（用户原文）、`summary`（来源已是汇总）、`embedded_dialogue`（内部请求中可明确识别的用户对话）、`error_evidence`（相关报错证据）。每题至少一个业务意图来源，只有`error_evidence`不够。

`inputs.origin`为`original`、`constructed`或`official`；`original`说明取得了哪份原件，`constructed`说明构造与业务关系，`official`保留真实URL及版本。未知附件不能标original。TraceID不是必有项，没有时保留可核对的文件和行／单元格定位，不生成假的标识。

`folder`是数据集下两级目录，`inputs.name`及`outputs.name`是普通文件名，不带路径。题面必须提到正式输出名。附件多于题面能逐个列出的数量时，可用附件清单与数量明确范围，但管理catalog仍逐个列全。

`scope_changes`记录例如“从真实复制归档收敛为归档台账，不再考查复制操作”。分类、能力、题面和计划交付同步反映范围变化。

## 工具结果

盘点脚本的`.inventory.json`记录每个输入文件的哈希、成功／失败状态及记录数。JSONL每条保留来源类型、文件、定位与原始值；不是自动选好的候选任务，必须继续语义筛选。

盘点输出使用新的工作文件名，脚本拒绝覆盖已有输出或原材料。结构检查报告必须保存在数据集目录外，与catalog分开；只有显式指定`--write-manifest`时才重建数据集的文件清单。

Excel数值保留XML原值、类型和数字格式信息，不自动解释日期序列或计算公式；结合日期系统、格式及工作表业务含义解释。共享公式保留其属性，必要时用表格解析能力展开。旧版`.xls`和其他不支持格式会明确标为未覆盖，需转换或另行解析，不能通过改后缀伪装格式。

结构检查报告中的`errors`必须解决；`warnings`要逐项判断，例如“文本包含模拟”可能是业务本意而非构造声明。原生容器通过也不证明所有业务内容已被检查，最终质量结论须按质量核查流程另写。
